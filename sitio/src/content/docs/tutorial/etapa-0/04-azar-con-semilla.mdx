Los juegos usan azar para casi todo: dónde aparece un enemigo, cómo rebota algo, cómo se arma un nivel. Pero una computadora no tira dados: **calcula**. Los números "al azar" salen de una cuenta que, vista de afuera, no parece tener ningún patrón. Por eso se llaman **pseudoaleatorios**.

`Math.random()`, el azar que trae JavaScript, empieza cada vez desde un lugar distinto, así que da otra secuencia cada vez. Para un juego eso es un problema:

- **No se puede repetir una partida**, ni ver de nuevo qué pasó.
- **No se puede compartir un experimento.** "Con este nivel el auto vuelca" no sirve si el nivel sale distinto cada vez.
- **El servidor y los jugadores no pueden ver lo mismo** sin mandarse cada número por la red.

Un generador **con semilla** resuelve las tres cosas. La **semilla** es el número desde el que empieza la cuenta: la misma semilla da **siempre** la misma secuencia de números.

El ejemplo arma un "nivel": 60 cubos con lugar, tamaño, color y giro sacados del azar.

**Qué probar:**

1. **Tocá "regenerar" varias veces.** Con semilla, sale siempre el mismo nivel. Mirá la consola: los primeros números son siempre los mismos.
2. **Cambiá la semilla**: otro nivel. Volvé a la anterior: vuelve el primero, idéntico.
3. **Activá "usar Math.random"** y regenerá: cada vez sale otro nivel, y no hay manera de volver a uno.

## El código, paso a paso

- **`azar.ts`** tiene el generador. `crearAzar(semilla)` guarda un **estado** (al principio, la semilla) y devuelve una función. Cada vez que se la llama, calcula el estado siguiente a partir del anterior y lo devuelve convertido en un número entre 0 y 1, igual que `Math.random()`.
- **La cuenta** es `estado = a · estado + c`, quedándose solo con los últimos 32 bits. Un número de **32 bits** es un entero entre 0 y 4.294.967.295 (2³² − 1). Al pasarse de ese tope, "da la vuelta", como el cuentakilómetros de un auto viejo. Esa vuelta es lo que mezcla los números.
- **`main.ts`** usa el generador como si fuera `Math.random`. Para cada cubo pide números: uno para el tamaño, uno para el color, tres para la posición y dos para el giro. Si la semilla es la misma, las respuestas son las mismas, y en el mismo orden.
- **Son dos módulos:** `azar.ts` no sabe nada de cubos, y `main.ts` no sabe cómo se calcula el azar. Se podría cambiar el generador por uno mejor sin tocar el resto.

## Lo importante

- **Un generador es un estado que se transforma.** Cada número sale del anterior con una cuenta fija.
- **Misma semilla, mismo nivel.** Y con el nivel, la misma partida, el mismo experimento, la misma prueba.
- **Separar el generador del que lo usa** permite cambiarlo sin tocar nada más.

## Más a fondo

<details>
<summary>Por qué estos números: 1664525 y 1013904223</summary>

Un generador `estado = a · estado + c` (módulo 2³²) puede caer en un ciclo corto y repetirse enseguida. Pero recorre **los 4.294.967.296 estados posibles** antes de repetir si se cumplen dos condiciones, que demostraron Hull y Dobell en 1962:

- `c` es impar: 1013904223 lo es.
- `a − 1` es múltiplo de 4: 1664525 − 1 = 1664524 = 4 × 416131.

Con números elegidos al azar, en cambio, el período puede ser mucho más corto.

</details>

<details>
<summary>El defecto de los bits bajos</summary>

Mirá solo el último bit del estado: como `a` y `c` son impares, en cada paso cambia. La secuencia del último bit es 0, 1, 0, 1… Los dos últimos bits se repiten cada 4 números, y en general el bit número `k` (contando desde 0) se repite cada `2^(k+1)` números.

Por eso el código divide el estado entero por 2³²: así mandan los bits altos, que son los que mejor se mezclan. Por eso también conviene no hacer `estado % 2` para tirar una moneda: saldría cara, ceca, cara, ceca…

</details>

:::caution[Sutilezas]

- **`Math.imul` multiplica como un procesador de 32 bits.** Una multiplicación común de JavaScript usa números con decimales de 64 bits: con números tan grandes, pierde los dígitos del final, justo los que la cuenta necesita.
- **Todo el azar que cambia el mundo tiene que salir del generador con semilla.** Basta **un** `Math.random()` escondido para que la repetición deje de dar igual. El azar puramente visual, como chispas o polvo, puede seguir con `Math.random()`.
- **El orden importa.** Si una versión nueva del código pide un número más antes de armar el nivel, todos los números siguientes se corren, y el nivel cambia aunque la semilla sea la misma.
- **Este generador es el más simple que hay**, y para un juego alcanza. Para claves o sorteos de verdad no sirve ninguno de estos: para eso existen los generadores criptográficos, como `crypto.getRandomValues()`.
  :::
